# 1 概述
## 1.1 适用范围和意义
为实现集中管理具备物联网功能的电池换电柜，建立统一的电池管理平台，特制定本电池/换电柜与平台互联TCP接口规范。

## 1.2 名词定义
| 名称 | 含义 | 备注 |
|------|------|------|
| DEV | 设备：电池/换电柜 |  |
| DEV-SERVER | 接入服务器 |  |

## 1.3 通讯规则
### 1.3.1 平台服务访问点
电池/换电柜采用 **域名+端口** TCP长连接接入：
- 域名：DNSNAME
- 端口：PORT
- 用途：分别适配电池、换电柜设备平台接入

### 1.3.2 通信规则
设备采用 **TCP/IP** 无线通信，正常保持**长连接**。

### 1.3.3 报文传输原则
1. 建链：设备发起连接，服务器鉴权通过方可接入；
2. 收发：定时属性上报、故障告警即时上报；
3. 鉴权：设备必须备案认证，未认证无法维持长连接；
4. 重连：连续10次发包失败 / 10分钟建链失败，重新发起连接。

## 1.5 报文格式
- 编码：**UTF-8 JSON**
- 协议版本：固定 **V2.0**
- 单报文最大长度：**5120字节**
- 时间格式：**13位时间戳**
- 报文禁止：回车、换行、空格、制表符；禁止十六进制，统一十进制数字。

### 1.5.1 报文类型编码
| 业务类型 | 请求类型 | 响应类型 | 报文编码 | 数据流方向 |
|----------|----------|----------|----------|------------|
| 登录 | 登录请求 | 登录响应 | 110 / 111 | 设备→平台 / 平台→设备 |
| 属性上报 | 属性上报请求 | 属性上报响应 | 310 / 311 | 设备→平台 / 平台→设备 |
| 告警上报 | 告警上报请求 | 告警上报响应 | 410 / 411 | 设备→平台 / 平台→设备 |
| 远程控制 | 远程控制请求 | 远程控制响应 | 500 / 501 | 平台→设备 / 设备→平台 |
| 配置查询 | 配置查询请求 | 配置查询响应 | 210 / 211 | 平台→设备 / 设备→平台 |

### 1.5.2 报文省略说明
报文字段可按需省略，无需全量携带，仅上报变化关键字段。

## 1.6 电池上报策略
### 1.6.1 性能上报策略
电池分**工作、存储、休眠**三种状态。

#### （1）工作状态：移动
- 无告警：5分钟上报常规属性；
- 定位/经纬度：30秒上报；
- SOC电量：60秒上报；
- BMS故障：告警后每60秒上报属性；
- 其他告警：告警后每2分钟上报属性；
- 轨迹转弯：每分钟最多8次经纬度补偿上报。

#### （2）工作状态：静止
- 无告警：10分钟上报常规属性；
- 定位/经纬度/SOC：2分钟上报；
- BMS故障：告警后60秒上报；
- 其他告警：告警后2分钟上报。

#### （3）存储状态
静止1小时无充放电自动进入；
- 断开长连接、关闭GPS；
- 默认60分钟上报一次；
- 触发充/放/移动/告警，立即退出存储。

#### （4）休眠状态
电压低进入保护，DTU+BMS停止工作；
- 默认24小时上报一次；
- 充电器插入唤醒设备。

> 固定默认周期：
> 移动5min、静止10min、存储60min、休眠24h。
> 遥控/遥调下发后，设备**立即上报对应遥测最新值**。

### 1.6.2 告警上报策略
1. 告警触发：上报告警开始；
2. 告警维持：未消除前每1小时重报；
3. 告警清除：连续5分钟无告警，上报告警结束；
4. 告警状态随常规遥测定时同步上报。

## 1.7 换电柜上报策略
### 1.7.1 遥测上报
- 上电永久长连接，**30秒定时增量上报**；
- 远程控制执行完成后，立即上报对应柜门/状态遥测；
- 每20分钟必须**全量上报**电池、柜门、单芯所有信号量。

### 1.7.2 告警上报
同电池策略：触发上报、每小时重报、连续5min正常才清除。

## 1.8 离线判断规则
### 平台侧
长连接**10分钟无数据交互**，强制断开。

### 电池离线
| 电池状态 | 离线判定条件 |
|----------|--------------|
| 移动/静止 | 20分钟无性能更新 |
| 存储 | 120分钟无性能更新 |
| 休眠 | 48小时无性能更新 |

### 换电柜离线
TCP断开 或 **20分钟无上报报文** 判定离线。

# 2 电池协议
## 2.1 登录
### 2.1.1 登录请求（msgType=110）
| 字段 | 是否必填 | 类型 | 说明 |
|------|----------|------|------|
| msgType | 是 | 整型 | 固定110 |
| imsi | 是 | 字符串 | SIM卡IMSI |
| batteryStatus | 是 | 字符串 | 电池状态编码 |
| hardVersion | 是 | 字符串 | 硬件版本 |
| softVersion | 是 | 字符串 | 软件版本 |
| devId | 是 | 字符串 | 设备唯一ID |
| protocolVersion | 是 | 字符串 | 协议版本V2.0 |
| devType | 是 | 整型 | 1=电池 |
| txnNo | 是 | 整型 | 13位时间戳 |

**示例**
```json
{
"msgType":110,
"imsi":"0123456",
"batteryStatus":"0",
"hardVersion":"",
"softVersion":"",
"devId":"B11231232",
"protocolVersion":"V2.0",
"devType":1,
"txnNo":1234567890123
}
```

### 2.1.2 登录响应（msgType=111）
| 字段 | 是否必填 | 类型 | 说明 |
|------|----------|------|------|
| msgType | 是 | 整型 | 固定111 |
| devId | 是 | 字符串 | 设备ID |
| result | 是 | 整型 | 1成功 0失败 |
| txnNo | 是 | 整型 | 对应请求流水号 |

**示例**
```json
{
"msgType":111,
"devId":"BAT000001",
"result":1,
"txnNo":1234567890123
}
```

## 2.2 属性上报

## 协议全景对照

本项目涉及三份协议，层次关系如下：

```
                        ┌──────────────────────────┐
                        │    云平台 (DEV-SERVER)     │
                        └────────────┬─────────────┘
                                     │ TCP JSON (V2.0)
                 ┌───────────────────┴───────────────────┐
                 │                                       │
        ┌────────┴────────┐                     ┌────────┴────────┐
        │   电池 DTU (★)   │                     │   换电柜 (★)     │
        │ (独立电池包上报)  │                     │  (Modbus 主机)   │
        └─────────────────┘                     └────────┬────────┘
                                                         │
                                                 RS485 (1路总线)
                                                 9600 8N1
                                                         │
                                       ┌─────────────────┼─────────────────┐
                                       │                 │                 │
                                       ▼                 ▼                 │
                                ┌──────────┐     ┌──────────┐             │
                                │BMS 保护板│     │充电器模块│    (可扩展)  │
                                │   (●)    │     │   (●)    │             │
                                │ 地址=1   │     │ 地址=0   │             │
                                │功能码    │     │功能码    │             │
                                │ 01/03    │     │ 03/06/0F │             │
                                └──────────┘     └──────────┘             │

  ★ = 协议中"换电柜/设备"角色 (发起/上报侧)
  ● = 从机/被控侧
```

**Modbus 主机/从机关系：**

换电柜作为 Modbus 主机，通过**同一路 RS485 总线**轮询两个从机，以从机地址区分：

| 从机 | 地址 | 功能码 | 协议 |
|------|------|--------|------|
| 充电器模块 | 0 | 03/06/0F | [换电柜仓位与充电器通信协议.md](%E6%8D%A2%E7%94%B5%E6%9F%9C%E4%BB%93%E4%BD%8D%E4%B8%8E%E5%85%85%E7%94%B5%E5%99%A8%E9%80%9A%E4%BF%A1%E5%8D%8F%E8%AE%AE.md) |
| BMS 保护板 | 1 | 01/03 | [铁塔BMS协议V3.0.md](%E9%93%81%E5%A1%94BMS%E5%8D%8F%E8%AE%AEV3.0.md) |

> 换电柜是总线上唯一的 Modbus 主机，负责轮询从机、下发控制指令。
> 电池 DTU 为独立电池包，以 TCP JSON 方式向平台上报，不在本 RS485 总线管辖范围。
