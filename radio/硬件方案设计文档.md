### 2.3 核心板选型对比与推荐

| 对比维度 | Orange Pi CM4 | 树莓派 CM4 | Radxa CM3 |
|---------|---------------|-----------|-----------|
| **SoC** | RK3566 (4×A55) | BCM2711 (4×A72) | RK3566 (4×A55) |
| **制程** | 22nm | 28nm | 22nm |
| **GPU Vulkan** | 1.1 (G52) | 不支持 | 1.1 (G52) |
| **NPU** | 0.8 TOPS | 无 | 0.8 TOPS |
| **PCIe** | 2.1 x1 | 2.0 x1 | 2.1 x1 |
| **视频编码** | 1080p100 H.265 | 1080p30 H.264 | 1080p100 H.265 |
| **功耗 (空闲)** | ~1.5W | ~2.5W | ~1.5W |
| **整板价格 (4GB+32G)** | ~$34 | ~$45+ | ~$40 |
| **生态成熟度** | 中 (Armbian支持好) | 高 | 中 |

**选型理由**：
- **功耗优势明显**：22nm 制程相比树莓派 CM4 的 28nm 更省电，对手持设备电池续航至关重要
- **GPU 更强**：Mali-G52 支持 Vulkan 1.1，模拟器性能上限更高 (PSP/Dreamcast 级别流畅)
- **视频编码能力强**：支持 1080p@100fps H.265 编码，为串流/录屏提供硬件加速
- **性价比高**：同内存/存储配置下价格约为树莓派 CM4 的 60-75%
- **CM4 兼容封装**：可直接使用树莓派 CM4 生态中的底板设计作为参考

**推荐配置**: Orange Pi CM4 **8GB RAM + 64GB eMMC** 版本，为多任务和大型模拟器 (N64/PSP) 提供充足内存余量。

### 2.5 核心板可升级性设计

核心板（Compute Module）是本掌机的"心脏"。随着瑞芯微新一代 SoC 的推出（RK3576、RK3588 及后续迭代），用户应当能够像升级内存条一样，仅更换核心板即可获得数倍的性能提升，而无需重新设计整块载板。

#### 2.5.1 升级动机

| 当前 | 未来升级 | 提升幅度 |
|------|---------|---------|
| **RK3566** (4×A55, Mali-G52) | **RK3576** (4×A72+4×A53, Mali-G57) | GPU ~3×, NPU 6 TOPS |
| **RK3566** | **RK3588S** (4×A76+4×A55, Mali-G610 MP4) | GPU ~8×, NPU 6 TOPS, PCIe 3.0, 8K |
| **模拟器上限 PSP/N64** | **PS2/GameCube/WiiU 流畅** | 质的跨越 |
| **功耗 ~5W (满载)** | **功耗 ~8-12W (满载)** | 需预埋散热余量 |

**性能提升对掌机体验的影响**：
- PSP 2× 分辨率 → PS2 3× 分辨率 + 60fps
- NPU 从 0.8 TOPS → 6 TOPS：本地 AI 超分（类似 DLSS）、实时语音翻译
- PCIe 2.1 x1 → PCIe 3.0 x2：NVMe SSD 速度翻倍

#### 2.5.2 物理兼容性分析——"插槽式"升级

好消息：Orange Pi CM4 采用与树莓派 CM4 相同的 **55 × 40mm** 物理封装和 **2× 100-pin + 1× 24-pin** 高密度 B2B 连接器。这个封装已经成为事实上的 ARM 核心板标准，市面上主要的 RK35xx 核心板均采用此规格：

```
┌──────────────────────────────────────────────────┐
│          载板 (Carrier Board)                      │
│                                                  │
│   ┌──────────────────────────────────┐           │
│   │  200-pin B2B 母座 (DF40C-100DP)  │           │
│   │  ┌────────────────────────┐     │           │
│   │  │                        │     │           │
│   │  │  核心板 (55×40mm)      │     │           │
│   │  │                        │     │  ← 像内存条一样
│   │  │  Orange Pi CM4 (现在)   │     │     按压/拔出
│   │  │        ↓ 升级           │     │
│   │  │  Radxa CM5 (未来)       │     │
│   │  │        ↓ 再升级          │     │
│   │  │  Orange Pi CM6 (远期)    │     │
│   │  └────────────────────────┘     │           │
│   └──────────────────────────────────┘           │
│                     ↑                            │
│              M2.5 固定螺丝 ×4                     │
└──────────────────────────────────────────────────┘
```

**当前可用的同封装升级选项**：

| 核心板 | SoC | CPU | GPU | NPU | PCIe | 功耗(TDP) | 价格(8+64G) | CM4脚位兼容? |
|--------|-----|-----|-----|-----|------|----------|-----------|------------|
| **Orange Pi CM4** | RK3566 | 4×A55 1.8G | Mali-G52 | 0.8T | 2.1 x1 | ~5W | ~$47 | ✅ 基准 |
| **Radxa CM3** | RK3566 | 4×A55 1.8G | Mali-G52 | 0.8T | 2.1 x1 | ~5W | ~$40 | ⚠️ 部分 |
| **Radxa CM5** | RK3588S | 4×A76+4×A55 | Mali-G610 MP4 | 6T | 3.0 x1 | ~10W | ~$75 | ❌ 需适配 |
| **Orange Pi CM5** | RK3588 | 4×A76+4×A55 | Mali-G610 MP4 | 6T | 3.0 x2 | ~12W | ~$85 | ❌ 需适配 |
| **Radxa NX5** | RK3576 | 4×A72+4×A53 | Mali-G57 MC4 | 6T | 2.1 x1 | ~8W | ~$55 | ❌ 不同封装 |

> **关键事实**：同一物理封装 ≠ 同一引脚定义。不同 SoC 的 IO 资源不同（如 RK3588 多出更多 PCIe lane、更多 USB 3.0），因此各家厂商的引脚分配必然不同。

#### 2.5.3 引脚兼容性详解

以最有吸引力的升级目标 **Radxa CM5 (RK3588S)** 为例，与当前 **Orange Pi CM4 (RK3566)** 做逐项对比：

```
功能信号        Orange Pi CM4 (RK3566)      Radxa CM5 (RK3588S)      兼容性
─────────────────────────────────────────────────────────────────────────────
HDMI TX         100-pin A 特定引脚           100-pin A 同类引脚          ⚠️ 脚位不同

SDMMC           1路 (SD3.0)                  1路 (SD3.0)                 ✅ 大概率相同
```

**核心结论**：物理封装相同，但引脚定义基本不兼容。**不能直接"热替换"**，但可以通过载板设计实现"开关式切换"。

#### 2.5.4 载板前向兼容设计策略

采用 **"通道预留 + 电阻选路"** 策略，在载板上为两个目标核心板的差异信号预留切换通道：

```
                 载板信号布线
                 ──────┬──────
                       │
              ┌────────┴────────┐
              │   0Ω 电阻跳线    │
              │  (SMD 0402)     │
              └──┬───────────┬──┘
                 │           │
         焊接位 A (RK3566)  焊接位 B (RK3588)
                 │           │
         ┌───────┴──┐   ┌───┴────────┐
         │ Orange Pi │   │  Radxa CM5 │
         │   CM4     │   │  (未来)    │
         └───────────┘   └────────────┘

切换方式:
  · 当前使用 Orange Pi CM4 → 0Ω 焊接在 A 位
  · 未来升级 Radxa CM5   → 0Ω 移至 B 位 + 刷入新设备树
  · 无需重新打板！仅需烙铁移两颗电阻
```

**需要预留切换的信号清单**（仅列出本项目实际使用且脚位不同的关键信号）：

| 信号 | RK3566 脚位 | RK3588S 脚位 | 载板处理方式 |
|------|-----------|-------------|-------------|
| HDMI_TX_CEC | Pin A-xx | Pin A-yy | 0Ω 电阻 2 选 1 |
| USB3_SS_TX/RX | Pin B-xx | Pin B-yy | 差分对, 0Ω×4 选路 |
| PCIe_TX/RX/CLK | Pin B-xx | Pin B-yy | 差分对, 0Ω×6 选路 |
| UART1 (ELRS) | Pin B-xx | Pin B-yy | 0Ω 电阻 2 选 1 |
| I2C0/I2C1/I2C2 | 各特定脚 | 各不同脚 | 0Ω 电阻 2 选 1×3组 |
| ETH_PHY (如需) | CM4 板载 | CM5 需外挂 | 预留 RTL8211F 焊盘 |

> **估计**：约 20-30 颗 0402 0Ω 跳线电阻即可覆盖全部差异信号。额外 BOM 成本 < $1，占用 PCB 面积约 15×20mm。

**载板版本策略**：

```
Carrier Board v1.0 (当前)
├── 默认适配: Orange Pi CM4 (RK3566)
├── 电阻配置: 出厂焊接 RK3566 路径
├── 预留通道: RK3588S 备用焊盘 (NC 悬空)
└── 升级时: 移电阻 + 刷新 dtb

Carrier Board v2.0 (未来)
├── 默认适配: Radxa CM5 (RK3588S)
├── 电阻配置: 出厂焊接 RK3588 路径
└── 同时保留 RK3566 回退能力
```

#### 2.5.6a 连接器选型分析——可更换接口的物理实现

可更换设计的核心在于连接器——它决定了"像换内存条一样换核心板"这个体验到底能不能实现。

**设计需求**：

| 需求 | 参数 | 说明 |
|------|------|------|
| 引脚数量 | ≥ 180 pins | 覆盖 DSI、CSI、HDMI、USB3、PCIe、I2C、SPI、UART、GPIO、供电 |
| 高速信号 | PCIe 3.0、USB3.0、MIPI DSI | 差分对需阻抗匹配，串扰 ≤ -30dB |
| 插拔寿命 | ≥ 100 次 | 支持用户多次升级和回退 |
| Z 高度 | ≤ 4.0mm (合高) | 掌机内部堆叠空间极其紧张 |
| 操作方式 | 免工具按压式 | 理想状态：手指按压即可插入/拔出 |
| 成本 | ≤ $5 (连接器对) | DIY 项目预算约束 |
| 供货 | 小批量可采购 | 非定制品，立创/得捷可零买 |

##### 设计原则

1. **差分对相邻**：每对差分信号放在相邻的奇偶 pin 上（如 D0+ 在 pin 11, D0- 在 pin 12），减小回路面积
2. **电源/GND 均匀散布**：每隔 10-15 个信号 pin 就插入一对电源/GND pin，降低地弹噪声
3. **高速信号靠近缺口**：PCIe、USB3 SS 等最高速信号靠近中央缺口区域，此处插座接触压力最大、信号完整性最好
4. **GPIO 放背面**：将数量多且速度低的 GPIO 集中在 Side B，避免干扰正面高速信号
5. **两侧 GND 包围**：每个功能块的差分对两侧都用 GND pin 隔离，防止串扰

##### 模块自动识别机制

Interposer 上通过 3 路 ADC 分压电阻编码来标识模块类型，载板读取后自动加载对应设备树：

| MODULE_ID[2:0] 电压比 | 识别结果 | 加载设备树 |
|----------------------|---------|-----------|
| 0.00 / 0.00 / 0.00 (全 GND) | **Orange Pi CM4 (RK3566)** | `rk3566-makeitdo.dtb` |
| 0.33 / 0.00 / 0.00 | Radxa CM3 (RK3566) | `rk3566-makeitdo.dtb` |
| 0.00 / 0.33 / 0.00 | **Radxa CM5 (RK3588S)** | `rk3588s-makeitdo.dtb` |
| 0.33 / 0.33 / 0.00 | Orange Pi CM5 (RK3588) | `rk3588-makeitdo.dtb` |
| 0.00 / 0.00 / 0.33 | Radxa NX5 (RK3576) | `rk3576-makeitdo.dtb` |
| 0.33 / 0.33 / 0.33 | 未知/自定义 | `base-makeitdo.dtb` (保守配置) |

```
载板侧电路 (每路):
  VCC3V3 ──┬── 上拉 10kΩ (载板) ──┬── MODULE_ID → ADC
           │                      │
           └──────────────────────┼── Interposer 金手指
                                  │
                     Interposer 侧编码电阻 (1%精度)
                     0Ω = GND (0.00)
                     3.3kΩ = 0.33 VCC
                     10kΩ = 0.50 VCC (预留)
                     悬空 = ~VCC
```

##### PCB 设计规则

| 规则 | 参数 | 说明 |
|------|------|------|
| 差分阻抗 (MIPI DSI/CSI) | 100Ω ±10% | 4对 lane + 1对 clock |
| 差分阻抗 (USB3 SS) | 90Ω ±10% | SuperSpeed TX/RX |
| 差分阻抗 (PCIe 3.0) | 85Ω ±10% | 8 GT/s, 需更严格匹配 |

| 差分对间等长 | ≤ 50 mil | DSI lane 之间等长 |

### 5.1 整体布局 (参考 Switch Pro 布局)

```
          ┌─────────────────────────────────┐
          │  [L] [LZ]              [RZ] [R] │  ← 肩键
          │                                 │
      ┌───┴────┐                   ┌────┴───┐
      │  摇杆L  │   ┌───────────┐   │  摇杆R  │

          │        └───────────┘        │

      │        │    [Start]        │        │

```

### 5.2 霍尔效应摇杆 ×2

| 参数 | 规格 |
|------|------|
| 传感器类型 | 霍尔效应 (非接触式) |
| 接口 | I2C (推荐) 或 模拟电压 (ADC) |
| 推荐型号 | **CJHALL-PI043** 或 **KS1113** |
| 供电 | 3.3V |
| 分辨率 | 12-bit ADC (4096 级) |
| 寿命 | ≥ 200万次循环 |
| I2C 地址 | 0x30 (左) / 0x31 (右) 通过地址选择引脚区分 |

**为什么选霍尔摇杆而非电位器摇杆？**
- 无物理接触，无磨损，寿命远超碳膜电位器摇杆
- 无漂移问题 (Switch 最大痛点)
- 精度更高，线性度更好

### 5.3 按键矩阵设计

使用 **4行 × 8列** 矩阵扫描，最多支持 32 个按键：

```
           COL0   COL1   COL2   COL3   COL4   COL5   COL6   COL7
           GPIO0  GPIO1  GPIO2  GPIO3  GPIO4  GPIO5  GPIO6  GPIO7
ROW0 GPIO8   A      B      X      Y     UP    DOWN   LEFT  RIGHT
ROW1 GPIO9   L      R     LZ     RZ     —      —      —      —
ROW2 GPIO10 Sel  Start   Home  Turbo   —      —      —      —
ROW3 GPIO11  —      —      —      —      —      —      —      —
```

按键连接示意 (以 A 键为例)：
```
ROW0 (GPIO8) ─────┬───── 按键 A ───── COL0 (GPIO0)
                   └───────┤  ├──────────────┘
```

**扫描方式**：
- 逐行拉低 ROW，读取 COL 状态
- 扫描频率 ≥ 100Hz (10ms 去抖动)
- 可通过 Linux `gpio-keys` 驱动或 `evdev` 上报

**肩键 (独立 GPIO)**：
- L / R / LZ / RZ 使用独立 GPIO 直连以降低延迟
- 按键类型：轻触开关 (ALPS SKHLLC / Omron B3F)

### 5.4 六轴 IMU (陀螺仪 + 加速度计)

### 5.7 背部自定义按键 (Back Paddles)

在掌机背部握持区域增加可自定义映射的背部按键（类似 Xbox Elite 手柄的拨片/背键），充分利用握持时中指和无名指的自然位置，为玩家提供额外的快速操作输入通道。

#### 5.7.1 设计目标

| 目标 | 说明 |
|------|------|
| **低延迟** | 独立 GPIO 直连，不经过按键矩阵扫描 |
| **舒适握持** | 位于中指/无名指自然放置位置，无需改变握姿即可触发 |
| **防误触** | 合理的触发力度 (≥120gf) 和短行程设计 |
| **可映射** | Linux evdev 暴露为独立输入事件，支持映射到任意按键/宏 |
| **可禁用** | 软件/硬件层面支持禁用，适应不同游戏习惯 |

#### 5.7.2 按键布局

采用 **4 按键方案**（左右各 2 个），排列方式参考 Xbox Elite 和 Steam Deck：

```
     后视图 (背部朝上)
┌──────────────────────────────────────────┐
│           北部 IO 区域                      │
│  ┌──────┐ ┌────┐ ┌──────┐ ┌────────┐    │
│  │USB-A │ │USB │ │Mini  │ │ 40-pin │    │
│  │ 3.0  │ │-C  │ │HDMI  │ │ GPIO   │    │
│  └──────┘ └────┘ └──────┘ └────────┘    │
│                                          │
│  ┌──────────────────────────────────┐    │
│  │      M.2 NVMe SSD 区域           │    │
│  └──────────────────────────────────┘    │
│                                          │
│  ┌──────────────────────────────────┐    │
│  │         散热格栅                  │    │

│                                          │
│  ┌─────────┐              ┌─────────┐   │  ← 握持区域上沿
│  │ [M1]    │              │    [M2] │   │  ← 中指位置 (上层)
│  │  ═══════│              │═══════  │   │

  M3: 左背下键 (对应左手无名指)
  M2: 右背上键 (对应右手中指)
  M4: 右背下键 (对应右手无名指)
```

**按键位置参考坐标** (PCB 坐标系, 背面视图原点为左下角)：

| 按键 | X (mm) | Y (mm) | 说明 |
|------|--------|--------|------|
| M1 (左背上) | 25.0 | 55.0 | 握把区上部, 中指自然位 |
| M3 (左背下) | 25.0 | 35.0 | 握把区下部, 无名指自然位 |
| M2 (右背上) | 175.0 | 55.0 | 握把区上部, 中指自然位 |
| M4 (右背下) | 175.0 | 35.0 | 握把区下部, 无名指自然位 |
| M1↔M3 垂直间距 | — | 20.0 | 上下分层清晰, 不易误触 |

#### 5.7.3 电气设计

背部按键采用 **独立 GPIO 直连** (与肩键同级)，不经过按键矩阵，确保最低延迟：

```
RK3566 GPIO              背部按键
────────────              ────────────
GPIO18  ◄──────────────── M1 (左背上键)
GPIO19  ◄──────────────── M3 (左背下键)
GPIO20  ◄──────────────── M2 (右背上键)
GPIO21  ◄──────────────── M4 (右背下键)

每个按键电路:
  VCC_3V3 ──┬── 上拉电阻 10kΩ ──┬── GPIO 输入
            │                   │
            └── 按键 ── GND     └── 100nF 去耦电容 → GND

电平逻辑: 按下 = 低电平 (Active Low)
           释放 = 高电平 (上拉)
```

> **注意**: 实际 GPIO 编号需根据 PCB Layout 最终分配。以上 GPIO18-21 为占位编号，建议优先选用带中断功能的 GPIO。

**防抖设计**：
- **硬件防抖**：100nF 电容 + 10kΩ 上拉组成 RC 低通滤波器，截止频率 ~160Hz
- **软件防抖**：Linux `gpio-keys` 驱动内置 debounce，配置 `debounce-interval = <5>`（5ms）

#### 5.7.4 机械结构要点

背部按键采用 **杠杆拨片式 + 轻触开关** 结构：

```
    外壳内壁                  外部
    ────────                  ──────

      ┌──────────────┐
      │   转轴支点    │  ← M1.6 不锈钢销轴
      │   (固定端)    │
      └──────┬───────┘
             │
    ┌────────┴────────┐
    │   铝合金拨片     │  ← 1.5mm 厚, 阳极氧化
    │   (杠杆臂)       │
    │                 │
    │    ┌────────┐   │
    │    │ 轻触开关 │   │  ← 焊接在 PCB 背面
    │    │ (触头)  │   │
    │    └────────┘   │
    │                 │
    └────────┬────────┘
             │
      ┌──────┴───────┐
      │   按压区域    │  ← 露出外壳表面 ~1.2mm
      │  (手指接触)   │     带防滑纹理
      └──────────────┘

  按压行程: 0.6mm (触发点) → 1.0mm (到底)
  杠杆比:   ~2:1 (手指端行程 / 触头端行程)
```

**按键规格**：

| 参数 | 规格 |
|------|------|
| 开关类型 | 轻触开关 (Tactile Switch) |
| 推荐型号 | **ALPS SKHLLC** 或 **Omron B3F-1000** |
| 触发力度 | 120 ± 20 gf (高于面板按键，防误触) |
| 行程 | 0.6mm (触发) / 1.0mm (到底) |
| 寿命 | ≥ 100万次 |
| 尺寸 | 6.0 × 6.0 × 4.3mm |
| 触感 | 段落感 + 清脆"咔嗒"反馈 |
| 拨片材质 | 铝合金 (1.5mm) 或 POM 工程塑料 |
| 拨片表面 | 同心圆防滑纹理 |

## 7. ELRS 射频控制子系统

ExpressLRS (ELRS) 是目前 FPV 穿越机、无人机、无人车和机器人领域最流行的开源射频遥控链路。本掌机将内置 ELRS 发射模组，摇杆和按键可直连遥控通道，让掌机变身为功能强大的无人机/无人车遥控器。

### 7.1 系统架构

```
│  │  CM4     │   TX/RX/CTS/RTS    │                         │    │
│  │          │                    │  ┌─────────┐ ┌───────┐  │    │
│  │ 摇杆→通道│    GPIO (BOOT/RST)  │  │ESP32-C3 │ │SX1280 │  │    │
│  │ 按键→开关│◄──────────────────►│  │ 主控MCU │ │RF前端 │  │    │
```

### 7.2 模组选型

#### 方案 A：M.2 E-Key 2230 可更换模组 (推荐)

ELRS 射频模组采用 **M.2 E-Key 2230** 封装，插在载板背面左侧 M.2 槽位上。用户可更换不同频段/功率的模组而不影响其他硬件。物理接口详见 [§9.4.2](#942-m2-e-key-2230--elrs-射频模组-左侧竖放)。

| 组件 | 型号 | 说明 |
|------|------|------|
| **主控 MCU** | ESP32-C3-MINI-1 或 ESP32-S3-MINI-1 | RISC-V 或 Xtensa 核心 |
| **射频前端** | SX1280IMLTRT | Semtech 2.4GHz 收发器, 与 ELRS 原生兼容 |
| **PA/LNA** | SE2431L (可选) | 功率放大器 + 低噪声放大器, 提升至 250mW/500mW |
| **TCXO** | 26MHz ±0.5ppm | 温补晶振, 保证频率稳定 |
| **RF 开关** | SKY13351 | SPDT 收发切换 (仅带 PA 时使用) |
| **射频连接** | M.2 卡上 IPEX MHF4 → u.FL 软线 → 背板 SMA | 天线可拆换 |

### 7.3 射频性能

| 参数 | SX1280 (无 PA) | SX1280 + SE2431L (带 PA) |
|------|---------------|-------------------------|
| **频率范围** | 2400 - 2480 MHz | 同 |
| **最大发射功率** | 12.5 dBm (~18 mW) | 24 dBm (~250 mW) |
| **接收灵敏度** | -132 dBm @ 50kbps | -135 dBm @ 50kbps |
| **数据速率 (LoRa)** | 50 - 2000 kbps | 同 |
| **ELRS 包率** | 25 - 1000 Hz | 同 |
| **理论距离 (250mW)** | — | ≥ 10km (LOS, 50Hz) |
| **实测距离 (典型)** | ~500m (无 PA) | 3-8km (带 PA, 空旷) |

> **建议**：带 PA/LNA 的版本更适合无人机/无人车远距离操控场景。但对机器人/近距离场景，无 PA 版本功耗更低，散热更好。

### 7.4 天线设计

- **连接器**：IPEX MHF4 (板端) → SMA-KE (外壳端)
- **天线类型**：
  - 可折叠棒状天线 (2dBi, 收纳方便, 类似 FPV 遥控器)
  - 或 固定式短棒天线 (1.5dBi)
- **天线位置**：背部上方 (北部扩展 IO 区域), 远离 CM4 板载 WiFi 天线以减少同频干扰
- **阻抗匹配**：50Ω 微带线, 需要 π 型匹配网络预留位

### 7.5 供电与功耗

| 运行模式 | 功耗 (无 PA) | 功耗 (带 PA, 250mW) |
|---------|------------|-------------------|
| **待机 (无发射)** | ~80 mA @ 3.3V (0.26W) | ~120 mA @ 3.3V (0.40W) |
| **10mW 发射** | ~120 mA @ 3.3V (0.40W) | ~180 mA @ 3.3V (0.59W) |
| **100mW 发射** | ~200 mA @ 3.3V (0.66W) | ~350 mA @ 3.3V (1.16W) |
| **250mW 发射** | N/A | ~500 mA @ 3.3V (1.65W) |

> 3.3V 供电需能稳定提供 ≥ 600mA (带 PA 时), 建议从系统 5V 轨经独立 LDO (如 AMS1117-3.3, 1A) 降压供给。

### 7.6 控制映射 (摇杆/按键 → ELRS 通道)

| 物理输入 | CRSF 通道 | 典型用途 |
|---------|----------|---------|
| 左摇杆 Y (上下) | CH1 | 油门 (Throttle) |
| 左摇杆 X (左右) | CH2 | 偏航 (Yaw) |
| 右摇杆 Y (上下) | CH3 | 俯仰 (Pitch) |
| 右摇杆 X (左右) | CH4 | 横滚 (Roll) |
| L 肩键 | CH5 (ARM) | 解锁/锁定电机 (2段开关) |
| R 肩键 | CH6 | 飞行模式切换 / 蜂鸣器 |
| LZ 肩键 | CH7 | 辅助开关 1 (如 Turtle Mode) |
| RZ 肩键 | CH8 | 辅助开关 2 (如 GPS Rescue) |
| 十字键 上/下 | CH9 (旋钮) | 图传功率 / OSD 参数调节 |

### 7.7 固件与配置

**ELRS 固件构建**：
- 使用 ExpressLRS Configurator (桌面版或 Web 版)
- 目标平台选择 `DIY_2400_TX_ESP32_SX1280_E28` (适用于 ESP32 + SX1280 方案)
- 通过 CM4 的 USB-C OTG 或 UART 进入 ESP32 烧录模式 (拉低 IO0 后复位)

**WiFi 配置模式**：
- 上电时 ESP32 默认进入 WiFi AP 模式 (SSID: `ExpressLRS TX`)
- 手机/PC 连接后通过浏览器访问 `http://10.0.0.1` 即可配置

**摇杆数据注入**：
- CM4 端运行一个 CRSF 数据注入程序, 从 `/dev/input/` 读取摇杆和按键事件
- 按 CRSF 帧格式封装为 26 字节 RC Channels Packed 帧
- 通过 `/dev/ttyS1` (UART1) 以 921600 bps 发送给 ELRS 模组
- 参考实现: [Arduino-Transmitter-for-ELRS](https://github.com/kkbin505/Arduino-Transmitter-for-ELRS)

### 7.8 安全注意事项

- **ARM 通道锁**：默认上电时 CH5 (ARM) 必须处于低位 (解锁需主动切换到高位), 防止意外启动
- **射频暴露**：250mW 模式下天线与人体的距离需 ≥ 20cm
- **频率合规**：使用 ELRS 前确认所在国家/地区的 2.4GHz 频段法规
- **散热**：250mW 持续发射时 SX1280 + PA 会明显发热 (~50°C), 需依赖系统散热风道

```
┌──────────┐     ┌─────────┐     ┌──────────┐
│电源按键   │────►│ 软开机  │────►│  RK809-5 │────► 系统启动
│(Power)   │     │ RC延迟  │     │  PMIC    │
└──────────┘     └─────────┘     └──────────┘
                                         │
                    ┌─────────────────────┘
                    ▼
              ┌──────────┐
              │ 长按6秒  │────► 强制关机
              └──────────┘
```

- **开机**：短按 Power 键 → RK809-5 上电 → SoC 启动
- **休眠**：系统进入 suspend-to-RAM (STR)，功耗 < 50mW
- **唤醒**：短按 Power 键或任意按键唤醒
- **强制关机**：长按 Power 键 ≥ 6秒

## 10. 散热与机械结构设计要点

### 10.1 散热方案

**RK3566 热特性**：
- TDP: ~5W (满载)
- 节流温度: ~85°C
- 推荐工作温度: < 70°C

**散热策略**：

```
┌─────────────────────────────────┐
│         铝合金散热片             │
│  ┌───────────────────────────┐  │
│  │   导热硅脂 / 导热垫        │  │
│  └───────────┬───────────────┘  │
│              │                   │
│       ┌──────┴──────┐           │
│       │  RK3566 SoC │           │
│       │  (CM4 顶层) │           │
│       └─────────────┘           │
└─────────────────────────────────┘
              │
      ┌───────┴───────┐
      │  微型涡轮风扇  │ (可选, 温控)
      │  25×25×6mm   │
      │  5V / 0.1A   │
      └───────────────┘
```

| 散热组件 | 规格 | 说明 |
|---------|------|------|
| 散热片 | 铝合金 40×30×5mm | 粘附于 CM4 SoC 上方 |
| 导热垫 | 1mm 厚, 6 W/mK | 填充 SoC 与散热片间隙 |
| 风扇 (可选) | 25×25×6mm 涡轮扇 | 5V PWM 温控, GPIO 驱动 |
| 风道 | 底部进风 → 背部出风 | 形成对流 |

**温控策略**：
- < 60°C: 风扇停转 (被动散热)
- 60-70°C: 风扇低转速 (PWM 30%)
- 70-80°C: 风扇中转速 (PWM 60%)
- > 80°C: 风扇全速 (PWM 100%) + CPU 降频

### 8.4 Joy-Con 式可拆卸手柄分析

**可行性**：低。主要制约因素：

1. **连接器复杂度**: Switch Joy-Con 使用专门设计的滑轨连接器 (Rail Connector)，包含多路数据、供电和结构卡扣，定制成本极高
2. **蓝牙通信**: 如果做成无线可拆卸手柄，需要独立的 MCU + 电池 + 蓝牙模块，每只手柄成本增加 $15-20
3. **结构强度**: 3D 打印外壳难以保证滑轨的精度和耐磨性

**推荐方案**：**一体式机身**，手柄不可拆卸。如确需分体，可考虑：
- 外接蓝牙手柄 (PS/Xbox 布局)
- 或者后期迭代升级为有线 USB-C 可拆卸模块

## 12. 应用场景与使用指南

本掌机不仅是游戏设备，更是一个多功能的 Linux 遥控平台。内置 ELRS 射频模组使其可直接控制无人机、无人车、机器人等设备。

### 11.1 无人机遥控 (FPV 穿越机)

```
┌─────────────┐      ELRS 2.4GHz      ┌─────────────┐
│   掌机      │ ◄──────────────────► │  无人机     │
│  (发射端)   │    CRSF 协议          │  (接收端)   │
│             │    50-1000Hz          │             │
│  摇杆→通道  │    ≤1ms 延迟          │  ELRS 接收机│
│  遥测显示   │                       │  → 飞控    │
└─────────────┘                       └─────────────┘
```

**典型配置**：
- **通道映射**：左摇杆 Y=油门, X=偏航; 右摇杆 Y=俯仰, X=横滚
- **解锁控制**：L 肩键 = ARM (解锁/锁定电机)
- **飞行模式**：R 肩键 = 模式切换 (Acro/Horizon/Angle)
- **辅助功能**：LZ/RZ = Turtle Mode / GPS Rescue
- **图传调节**：十字键 = 图传功率 / OSD 参数

**推荐搭配飞控**：
- Betaflight / INAV / ArduPilot 固件
- ELRS 接收机 (如 BetaFPV ELRS 2.4G, HappyModel EP系列)
- 5.8GHz 图传 + FPV 眼镜 (可选)

### 11.2 无人车遥控 (地面车辆)

**应用场景**：
- 遥控车 (RC Car) 竞速/攀爬
- 无人巡检车
- 自动驾驶开发平台

**通道映射示例**：

| 通道 | 物理输入 | 用途 |
|------|---------|------|
| CH1 | 左摇杆 X | 转向 (Steering) |
| CH2 | 左摇杆 Y | 油门 (Throttle) |
| CH3 | 右摇杆 Y | 刹车 (Brake) |
| CH4 | 右摇杆 X | 辅助通道 |
| CH5 | L 肩键 | 解锁/锁定 |
| CH6 | R 肩键 | 灯光/喇叭 |

**推荐搭配**：
- ESP32/STM32 主控 + ELRS 接收机
- PCA9685 舵机驱动板
- 电机驱动 (L298N / TB6612)

### 11.3 机器人遥控

**应用场景**：
- 机械臂控制
- 轮式/履带式机器人
- 四足机器人 (Spot 类)

**高级控制模式**：
- **手动模式**：直接控制关节/运动
- **半自主模式**：掌机发送高层指令，机器人自主执行
- **编程模式**：通过 WiFi 连接，使用 Python/C++ 编程控制

**机械臂通道映射示例**：

| 通道 | 物理输入 | 机械臂关节 |
|------|---------|-----------|
| CH1 | 左摇杆 X | 底座旋转 (Base) |
| CH2 | 左摇杆 Y | 肩部 (Shoulder) |
| CH3 | 右摇杆 Y | 肘部 (Elbow) |
| CH4 | 右摇杆 X | 腕部旋转 (Wrist) |
| CH5 | L 肩键 | 夹爪开合 (Gripper) |
| CH6 | R 肩键 | 模式切换 |

### 11.4 多设备切换

掌机支持通过 ELRS 配对存储多个接收机，可快速切换控制不同设备：

```
┌─────────────┐
│   掌机      │
│             │
│  配对列表:  │
│  1. 穿越机A │ ← 当前连接
│  2. 无人车B │
│  3. 机械臂C │
│  ...        │
└─────────────┘
```

**切换方式**：
- ELRS WiFi 配置页面切换
- 或通过 OSD 菜单 (如连接 FPV 眼镜时)

### 11.5 遥测数据回传

ELRS 支持双向遥测，掌机可实时显示：

| 遥测参数 | 来源 | 显示方式 |
|---------|------|---------|
| RSSI (信号强度) | ELRS 协议 | 屏幕/OSD |
| LQ (链路质量) | ELRS 协议 | 屏幕/OSD |
| 电池电压 | 飞控/车载电调 | 屏幕/OSD |
| GPS 坐标 | GPS 模块 | 屏幕/OSD |
| 高度/速度 | 气压计/GPS | 屏幕/OSD |
| 温度 | 传感器 | 屏幕/OSD |

### 11.6 扩展能力

**背部接口扩展**：
- **USB-A 3.0**：外接 USB 游戏手柄、键鼠、U盘
- **USB-C OTG**：连接 PC 进行 ADB 调试、固件烧录
- **40-pin GPIO**：连接外部传感器、执行器、自定义硬件
- **M.2 NVMe**：大容量存储 (游戏 ROM、机器人地图数据等)

**软件扩展**：
- **Python/Node-RED**：可视化编程控制机器人
- **ROS 2**：机器人操作系统集成
- **MQTT**：物联网设备联动
- **Web 控制面板**：通过浏览器远程监控
