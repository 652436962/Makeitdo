## 1. 项目概述

### 1.1 背景

掌机项目内置 ELRS 2.4GHz 射频模组（ESP32-C3 + SX1280，M.2 E-Key 插槽），可作为无人机/无人车/机器人的遥控器。硬件上 ELRS 模组通过 **UART1** 与主控 RK3566 直连，使用 CRSF（Crossfire）串行协议通信。

软件方案设计文档已确定 ELRS 控制采用 **Qt 一体化方案（elrs-qt）**：由 Qt 应用直接通过串口与 ELRS 模组交互，界面、协议、串口管理全部收敛在一个应用内（早期 Rust 后台服务方案已废弃）。本计划书是该方案的开发执行计划。

### 1.2 目标

- 在 Linux 下用 Qt 应用直接打开串口（`/dev/ttyS1` 或 `/dev/ttyUSB0`），与 ELRS TX 模组完成 CRSF 协议交互；
- 将摇杆/按键（evdev）输入实时映射为 CRSF 遥控通道并发送，作为**掌机遥控模式**的核心；
- 解析并可视化 ELRS 回传遥测（RSSI / 链路质量 / 接收机电压 / GPS 等）；
- 提供通道映射配置、串口连接管理、ELRS 固件升级等完整工具链；
- 同一代码库可运行于 RK3566 掌机与普通 x86 PC（接 USB-TTL 转接板 + ELRS 模组），便于开发调试。

### 1.3 范围

**本计划书涵盖：**

- 应用层架构、串口通信、CRSF 协议封装、界面设计、开发里程碑与测试方案。

**不在范围内：**

- ELRS 模组端固件开发（直接使用官方 ExpressLRS TX 固件，目标 `DIY_2400_TX_ESP32_SX1280_E28`）；
- 底板硬件设计（见硬件方案设计文档）；
- 4G 图传、OSD 视频叠加（由现有软件方案中的其他模块负责，本应用通过 DBus/共享内存向外提供遥测数据接口）。

## 2. 硬件环境

### 2.1 掌机目标硬件（RK3566）

| 项目 | 规格 | 说明 |
|------|------|------|
| 主控 | Orange Pi Compute Module 4 (RK3566) | Quad A55 @ 1.8GHz |
| ELRS 模组 | M.2 E-Key 2230 自定义模组 | ESP32-C3 + SX1280，跑 ExpressLRS TX 固件 |
| 串口 | UART1 | 板卡引脚映射到 `/dev/ttyS1` |
| 流控 | CTS/RTS 硬件流控 | 921600 bps 下必配 |
| 控制 GPIO | ELRS_BOOT / ELRS_RST | libgpiod 操作，用于进入下载模式 |
| 天线 | IPEX → SMA | 2.4GHz，背部引出 |

### 2.2 开发调试硬件（x86 PC）

| 项目 | 说明 |
|------|------|
| USB-TTL 转接板 | CH340/CP2102，3.3V 电平，需与模组 TX/RX 交叉连接 |
| 波特率 | 921600 8N1（ELRS 默认串口参数） |
| 设备节点 | `/dev/ttyUSB0`（自动枚举，需加入 `dialout` 用户组） |

### 2.3 串口引脚映射（RK3566 掌机底板）

```
RK3566 UART1                  ELRS 模组 (M.2 E-Key)
┌────────────┐                ┌──────────────────┐
│ UART1_TX   ├───────────────►│ RX               │
│ UART1_RX   │◄───────────────┤ TX               │
│ UART1_CTS  │◄───────────────┤ RTS              │
│ UART1_RTS  ├───────────────►│ CTS              │
│ GPIO (BOOT)├───────────────►│ IO0 (下载模式)    │
│ GPIO (RST) ├───────────────►│ EN (复位)         │
└────────────┘                └──────────────────┘
```

> 注意：920k 波特率下必须启用硬件流控，防止 ESP32 侧缓冲区溢出导致丢帧。

## 3. 软件架构设计

### 3.1 技术选型

| 层次 | 选型 | 理由 |
|------|------|------|
| 框架 | Qt 6（LTS），最低 Qt 5.15 | RK3566 的 Armbian/Debian 12 仓库自带，跨 x86/ARM |
| 串口 | QSerialPort（QtSerialPort 模块） | 官方跨平台串口封装，事件驱动，支持流控设置 |
| 输入 | libevdev（通过 QSocketNotifier 集成） | 读取摇杆/按键 evdev 事件，低延迟 |
| 构建 | CMake + Qt6 包 | 与掌机项目软件栈一致 |
| 配置 | JSON（QJsonDocument） | 通道映射/串口参数持久化 |
| 数据外发 | 共享内存 + DBus（可选） | 供 OSD 叠加、桌面小组件消费遥测 |

### 3.3 线程模型

| 线程 | 职责 | 说明 |
|------|------|------|
| 主线程 | Qt 事件循环、界面刷新 | 定时器 60Hz 刷新通道条/遥测仪表 |
| 串口线程 | 读写 `/dev/ttyS1` | QSerialPort 随线程移动；读就绪信号 → 解析 → 信号回主线程 |
| 输入线程 | 阻塞读 evdev | libevdev 阻塞读，事件经队列投递到协议层 |

> 关键设计：串口写入集中在**发送定时器**（按 ELRS 包率 25~500Hz 可配）中执行，避免界面操作直接触发写串口导致时序抖动。

### 3.4 关键数据流

```
遥控数据流（发送）:
  evdev 摇杆/按键 → ChannelMap 映射 (死区/反向/范围) → 16路 11-bit 通道值
    → CrsfFrameBuilder 打包 (0x16 RC Channels Packed) → QSerialPort 写入 → ELRS 模组

遥测数据流（接收）:
  QSerialPort 读就绪 → CrsfFrameParser 粘包/CRC校验 → 类型分发
    → TelemetryStore → 界面信号 (RSSI/LQ/电压/GPS 仪表) + 共享内存外发
```

## 4. 串口通信设计

### 4.1 串口参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 设备 | `/dev/ttyS1`（掌机）/ `/dev/ttyUSB0`（PC） | 可在界面选择 |
| 波特率 | 921600 | ELRS 默认 |
| 数据位/校验/停止位 | 8N1 | |
| 流控 | 硬件 (CTS/RTS) | 920k 必须；USB-TTL 无流控线时降级 420000 验证 |

### 4.2 CRSF 帧格式（本应用涉及的帧类型）

```
┌──────────┬─────────────────────┬──────────┬──────────┬──────────┐
│ 地址 0xC8 │ 长度 (payload+2)     │ 类型      │ Payload  │ CRC8     │
│  1 字节   │ 1 字节              │ 1 字节   │ N 字节    │ 1 字节    │
└──────────┴─────────────────────┴──────────┴──────────┴──────────┘
CRC8: 多项式 0xD5 (CRC-8-DVB-S2)，从"类型"字节起算，含 Payload
```

| 类型 | 名称 | 方向 | 本应用处理 |
|------|------|------|-----------|
| 0x16 | RC Channels Packed | 应用 → 模组 | 核心发送：16 通道 11-bit 位打包 |
| 0x14 | Link Statistics | 模组 → 应用 | RSSI / LQ / SNR / 发射功率 → 界面 |
| 0x02 | GPS | 模组 → 应用 | 经纬度/海拔/卫星数 → 遥测页 |
| 0x08 | Battery Sensor | 模组 → 应用 | 接收机电压/电流/消耗 → 警告 |
| 0x1B | Flight Mode | 模组 → 应用 | 飞行模式 → 状态栏 |
| 0x1C | Device Info | 双向 | 设备信息 → 诊断页 |
| 0x29 | MSP 透传 | 双向 | 预留（Betaflight 配置透传） |

### 4.3 RC 通道值编码

- 通道值：11-bit（0~2047），对应脉宽 988~2012 µs，默认居中 1500 µs；
- 打包：16 通道按位连续打包进 22 字节 Payload（大端位流）；
- 发送节拍：按 ELRS 包率配置（25/50/100/150/250/500 Hz），默认 250 Hz（4ms 周期）。

### 4.4 健壮性设计

| 问题 | 对策 |
|------|------|
| 粘包/半包 | 按 `len` 字段做状态机拆帧，超时丢弃缓冲 |
| CRC 错误 | 静默丢弃并计数，界面显示"误帧率"诊断指标 |
| 串口断开 | QSerialPort::errorOccurred → 弹窗 + 通道值安全归零（油门回中/最低） |
| 应用退出 | 退出前发送 2 帧"安全通道值"（油门最低、ARM 关闭）再关闭串口 |
| 发送超时 | 写超时 10ms，超时计数累加，连续失败提示链路异常 |

### 4.5 固件升级路径

Qt 应用内集成 esptool 调用（或内嵌 esptool 的 `--port` 直传模式）：

```
界面"固件升级"页 → 关串口 → gpioset 拉低 BOOT → 复位进入下载模式
  → 启动 esptool.py --chip esp32c3 --port /dev/ttyS1 --baud 921600 write_flash ...
  → 完成 → 复位运行 → 重新打开串口 → 校验 Device Info
```

## 5. Qt 界面设计

### 5.1 界面框架

- 单窗口多页面（QTabWidget）或侧边导航 + QStackedWidget；
- 分辨率适配 1080×1920 竖屏（掌机）与桌面横屏；QML 方案天然支持响应式布局，推荐 **Qt Quick (QML)**，若团队更熟悉 Widgets 则用 QWidget + 样式表，二者架构层完全复用；
- 深色主题（FPV 场景防眩光）。

### 5.3 信号槽与数据绑定要点

- `SerialDevice::frameReady(QByteArray)` → 协议层解析 → `TelemetryStore::updated(Telemetry)` → 界面绑定；
- 通道值变更用高频信号（≥250Hz），界面侧用定时器合并刷新（60Hz）防止过度重绘；
- 所有跨线程信号使用 Qt::QueuedConnection。

## 8. 测试计划

### 8.1 分层测试

| 层级 | 方法 | 工具 |
|------|------|------|
| 单元测试 | 协议编解码、CRC8、通道映射、粘包拆分 | Qt Test (QTest) + CTest |
| 协议仿真 | 回环串口（socat pty 对）注入预设遥测帧，校验解析结果 | socat + 测试脚本 |
| 硬件联调 | x86 PC + USB-TTL + ELRS 模组 → 接收机实测 | 逻辑分析仪抓 UART 波形 |
| 掌机集成 | RK3566 实机全流程（含 GPIO 下载模式） | 掌机整机 + Betaflight 地面站 |

### 8.2 关键测试用例

1. **帧格式**：16 通道边界值（988/1500/2012）打包 → 回解一致；
2. **粘包**：一次性灌入多帧 + 半帧，状态机正确拆分，无丢帧；
3. **断连**：热拔串口 → 通道值安全归零、界面告警、重连可用；
4. **流控**：920k 下 ESP32 侧收满 1 分钟 250Hz 帧无溢出丢帧；
5. **长稳**：连续运行 2h，内存无增长（valgrind/heaptrack 检查）。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 920k 波特率丢帧（USB-TTL 缓冲不足） | 高 | 硬件流控优先；USB-TTL 选带流控型号；可降级 420k 联调 |
| ESP32-C3 供电不足导致射频掉链 | 中 | 底板供电按硬件方案执行（3.3V ≥ 500mA 独立 LDO） |
| 11-bit 位打包实现错误 | 中 | 与官方 crossfire 库测试向量对拍；QTest 覆盖全边界 |
| evdev 热插拔/设备号漂移 | 中 | 按设备名/物理路径（by-id）匹配，热插拔监听重连 |
| Qt 版本差异（RK3566 仓库 Qt 5.15 vs PC Qt 6） | 中 | 代码限定在两者公共 API 子集；CI 双版本构建 |
| 界面高频刷新导致 RK3566 卡顿 | 低 | 60Hz 合并刷新 + 仪表用轻量 QML 图形 |
